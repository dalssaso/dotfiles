* Overview

Herdr is a terminal workspace manager built for AI coding agents. It is a
multiplexer like tmux -- a background server owns the terminal processes, so
panes survive detaching -- with two differences that matter:

1. *Mouse-first.* Click panes, drag split borders, right-click for a pane menu.
   Keyboard is optional rather than mandatory.
2. *Agent-aware.* It detects panes running =claude=, =codex=, and friends, and
   shows each one's state in a sidebar across every project at once:
   =working=, =blocked=, =done=, =idle=, =unknown=.

The second point is the reason to use it. Agents fail quietly -- they stop and
wait for input. Without a sidebar you find that out by cycling through panes.

*Docs:* https://herdr.dev/docs/

* Installation

Herdr is declared in =Brewfile.common= alongside everything else:

#+begin_src ruby
brew "herdr"
#+end_src

That is the only thing that needs to be checked in. On a fresh machine,
=.chezmoiscripts/darwin/run_onchange_before_install-packages.sh.tmpl= embeds a
=sha256sum= of =Brewfile.common= as a comment, so editing the Brewfile changes
the script hash and chezmoi re-runs =brew bundle= on the next =chezmoi apply=.

#+begin_src fish
herdr --version
#+end_src

** Shell completions

Homebrew's formula installs zsh completions only. Fish completions are generated
from the binary and checked in at
=dot_config/private_fish/completions/herdr.fish=. Regenerate after a version
bump that adds subcommands, then re-add to chezmoi:

#+begin_src fish
herdr completion fish > ~/.config/fish/completions/herdr.fish
chezmoi add ~/.config/fish/completions/herdr.fish
#+end_src

** Keeping the server running

#+begin_src fish
brew services start herdr   # optional: persistent across reboots
herdr                       # or just let it start on first use
#+end_src

* The Ghostty handoff

/This is the most important thing in this document./

Ghostty previously implemented its own tmux-style =ctrl+a= prefix for tabs,
splits, and split navigation. Herdr now owns that prefix, and *every*
=ctrl+a>= binding was removed from =dot_config/ghostty/config=.

That removal is not optional or cosmetic. Ghostty *consumes* a leader key:
pressing =ctrl+a= puts Ghostty into a pending-sequence state and buffers the
keypress rather than forwarding it to the running program. This is precisely
what Ghostty's =end_key_sequence= action exists to undo. So if a single
=ctrl+a>= binding survives in the Ghostty config, Ghostty swallows =ctrl+a= and
Herdr never receives its prefix at all.

*If the Herdr prefix ever stops responding, check the Ghostty config for a
=ctrl+a>= line first.*

What changed:

| Was                            | Now                                       |
|--------------------------------+-------------------------------------------|
| =ctrl+a>c/n/p/o=  tabs         | Herdr tabs                                |
| =ctrl+a>\= =ctrl+a>minus=      | Herdr splits (=prefix+v= / =prefix+minus=) |
| =ctrl+a>h/j/k/l=  goto_split   | Herdr pane focus                          |
| =ctrl+a>x=        close_surface | Herdr =close_pane=                        |
| =ctrl+a>equal=    equalize     | dropped                                   |
| =ctrl+shift+hjkl= resize_split | Herdr direct pane resize                  |
| =ctrl+a>q=        quit Ghostty | Herdr *detach* -- see below               |
| =ctrl+a>r=        reload_config | =cmd+shift+r=                            |
| --                             | quit is native =cmd+q=                    |

Two behaviour changes worth internalising:

- =ctrl+a= then =q= used to *quit Ghostty*. It now *detaches* -- the client
  exits, the server and every agent keep running, and you land back at the fish
  prompt. Run =herdr= to reattach exactly where you left off. This is tmux's
  =prefix+d=.
- Split-right was =ctrl+a>\=; it is now =prefix+v=. =backslash= is not among
  Herdr's documented punctuation key names (=minus=, =comma=, =ampersand=,
  =plus=, =backtick=), so it was not worth betting on.

* Concept model

#+begin_example
herdr server               persistent, survives detach
└── Session                server namespace  (--session <name>)
    └── Workspace          one per project
        └── Tab            layout separator
            └── Pane       a terminal: shell, agent, TUI
#+end_example

An *agent* is a recognized process inside a pane. Herdr identifies it and tracks
its state; that is what populates the sidebar.

*Modes:*

- *Terminal mode* -- the default. Keys go to the program in the pane.
- *Prefix mode* -- entered with =ctrl+a=. The next chord is a Herdr command.
- *Navigate mode* -- movement shortcuts win while it is open.
- *Copy mode* -- vim-style selection over the scrollback.

* Daily workflow

#+begin_src fish
cd ~/src/some-project
herdr                       # launch or attach

herdr --session review      # a separate named server namespace
herdr --remote myhost       # attach to a Herdr server over SSH
herdr status                # local client and server status
#+end_src

Inside a pane, start an agent normally (=claude=, =codex=). Herdr picks it up --
no wrapper command.

** Git worktrees

Herdr creates and tracks git worktrees as workspaces, checked out under
=~/.herdr/worktrees=. Default binding =prefix+shift+g=.

That directory sits outside the =includeIf gitdir:= scopes in =~/.gitconfig=,
which looks like it would break per-account git identity. *It does not.*
=includeIf gitdir:= matches the *main repository*, not the linked worktree -- a
worktree of an =~/src/oss= repo created under =/tmp= still resolves the oss
identity. Verified empirically; no mitigation needed.

* Agent integration

Herdr detects agents heuristically on its own -- the sidebar works with nothing
installed. The optional integration installs a hook that lets the agent report
its *session reference* back to Herdr.

#+begin_src fish
herdr integration status          # 17 supported agents, install state each
herdr integration install claude
#+end_src

*What it actually does, precisely:* it reports the session id and transcript path
only. It does /not/ improve working/blocked/done detection -- that stays
heuristic. Its single purpose is enabling
=session.resume_agents_on_restore = true=, which without it is a silent no-op:
agent panes come back as plain shells after a server restart instead of resuming
their conversations.

** Footprint

Installing =claude= writes =~/.claude/hooks/herdr-agent-state.sh= and adds one
=SessionStart= entry to =~/.claude/settings.json=. Existing hooks are preserved
-- the installer appends rather than replacing.

The script is defensive by construction, verified by reading it:

- Exits 0 immediately unless =HERDR_ENV=1= and =HERDR_SOCKET_PATH= and
  =HERDR_PANE_ID= are all set, so it is *completely inert outside a Herdr pane*.
- Ignores every action but =session=, and skips subagents entirely.
- Sends one JSON-RPC =pane.report_agent_session= message over a local unix
  socket with a 0.5s timeout, swallowing all exceptions. It cannot hang or fail
  a Claude Code session.
- Cleans its temp file via a =trap=.

Verified: inert outside Herdr, exit 0 against a dead socket, exit 0 for
subagents, no temp files leaked.

** Not tracked in chezmoi -- deliberately

The script's own header reads:

#+begin_quote
managed by herdr; reinstalling or updating the integration overwrites this file.
add custom hooks beside this file instead of editing it.
#+end_quote

It is versioned (=HERDR_INTEGRATION_VERSION=) and Herdr replaces it on upgrade,
so checking it into chezmoi would set up a fight between the two over the same
file. Track the /command/ instead of the /artifact/ if this needs to survive a
machine rebuild. Note that =~/.claude/= is not chezmoi-managed at all today.

Check for drift after a Herdr upgrade:

#+begin_src fish
herdr integration status   # "current (vN)" vs "outdated"
#+end_src

** Agent layer

=alt= is the agent modifier, because =prefix+h/j/k/l= is already pane focus.

| Action         | Binding           |
|----------------+-------------------|
| Next agent     | =prefix+alt+j=    |
| Previous agent | =prefix+alt+k=    |
| Focus agent /n/ | =prefix+alt+1..9= |

The sidebar is sorted by =priority=, so blocked agents float to the top and
these bindings walk an attention queue rather than a static project tree.

* Copy, paste, and scrolling

Notably less painful than tmux, mostly because the common case needs no mode.

** Mouse

- *Drag-select copies* straight to the system clipboard (=copy_on_select = true=).
  No mode, no prefix. A toast confirms it.
- Wheel scrolls the pane scrollback, three lines per notch
  (=mouse_scroll_lines=).
- Real draggable scrollbars beside each pane (=pane_scrollbars=).
- Paste is =cmd+v=, native. Ghostty already sets =clipboard-read = allow= and
  =clipboard-write = allow=, so nothing is in the way.

** Copy mode

Enter with =prefix+[=.

| Purpose   | Keys                                             |
|-----------+--------------------------------------------------|
| Move      | =h/j/k/l=, =w/b/e=, =W/B/E=, ={= =}=             |
| Page      | =PageUp/PageDown=, =ctrl+b= / =ctrl+f=           |
| Half page | =ctrl+u= / =ctrl+d=                              |
| Search    | =/= forward, =?= backward, =n= / =N= to repeat   |
| Select    | =v= or =Space=                                   |
| Copy      | =y= or =Enter=                                   |
| Exit      | =q= or =Esc= (Esc clears selection/search first) |

Search is case-insensitive unless the query contains an uppercase letter.

Two improvements over tmux: copy mode *does not pause the pane* -- output stays
live, follows at the bottom, and stays pinned when you scroll into history. And
the vim keys are simply there; there is no vi-mode option to set first.

=ctrl+b= and =ctrl+f= page within copy mode without colliding with anything,
since the prefix is =ctrl+a=.

=prefix+e= dumps the pane scrollback into your editor -- the escape hatch when
the whole buffer belongs in Emacs.

** Cmd+click on URLs -- open question

=ui.mouse_capture = true= (kept, since mouse-first is the point) means Herdr
handles clicks rather than the terminal. Herdr's own config comment says setting
it =false= is what lets "the terminal handle normal clicks, such as Cmd-clicking
URLs."

Ghostty's documentation does not describe Cmd+click behaviour under application
mouse reporting, so this is *untested*. Expected workaround is *Shift+click*, the
conventional bypass for mouse reporting. If that fails and opening URLs from
panes matters, set =mouse_capture = false= and drive Herdr from the keyboard.

(=right_click_passthrough_modifier= exists but forwards right-click gestures
only, and explicitly rejects Shift.)

* Configuration

Config lives at =~/.config/herdr/config.toml=, tracked in chezmoi at
=dot_config/herdr/config.toml=. Only values differing from the defaults are set.

Print the fully commented defaults for reference -- this is authoritative for the
installed version, unlike the website:

#+begin_src fish
herdr --default-config
#+end_src

Validate and reload without restarting the server:

#+begin_src fish
herdr config check                 # -> "config: ok"
herdr server reload-config         # or prefix+shift+r
herdr config reset-keys            # back up and strip custom keybindings
#+end_src

** What is set, and why

| Setting                              | Value                 | Reason                                                         |
|--------------------------------------+-----------------------+----------------------------------------------------------------|
| =keys.prefix=                        | =ctrl+a=              | Reuses existing muscle memory; Ghostty gave up the leader      |
| =theme.name=                         | =terminal=            | Inherits Ghostty's Ayu palette, and its light/dark switch      |
| =ui.accent=                          | =green=               | Reads from the terminal palette                                |
| =ui.agent_panel_sort=                | =priority=            | Blocked agents float to the top                                |
| =ui.status_indicators=               | =symbols=             | Distinct glyphs beat color-only dots                           |
| =ui.window_title=                    | ={workspace} · {tab}= | See below                                                      |
| =ui.toast.delivery=                  | =system=              | Reaches Notification Center when Ghostty is not focused        |
| =advanced.scrollback_limit_bytes=    | =50000000=            | Agent output is verbose; 10 MB default truncates               |
| =keys.next_agent= / =previous_agent= | =prefix+alt+j/k=      | Agent layer on alt                                             |
| =keys.focus_agent=                   | =prefix+alt+1..9=     | Direct jump                                                    |
| =keys.last_pane=                     | =prefix+tab=          | Back-and-forth                                                 |
| =keys.cycle_pane_next=               | ="" (cleared)         | Owns prefix+tab by default; must be cleared to free it         |
| =keys.resize_pane_*=                 | =ctrl+shift+hjkl=     | Chords freed when Ghostty's split-resize was removed           |

*Deliberately left at defaults:*

- =terminal.default_shell = ""= resolves =$SHELL= -> fish.
- =terminal.shell_mode = "auto"= uses *login shells on macOS*. This is
  load-bearing: it is what puts mise shims and Homebrew paths in every pane.
- =terminal.new_cwd = "follow"= inherits the source pane, which is better than
  Ghostty's =working-directory = home=.
- =session.resume_agents_on_restore = true= resumes agent panes into their native
  conversations after a server restart.
- =experimental.allow_nested = false= -- relevant because agents running inside
  panes may try to launch =herdr=.
- =worktrees.directory = "~/.herdr/worktrees"= -- safe, see above.

** Window title

=ui.window_title= is written to the *outer* terminal, which with
=macos-titlebar-style = tabs= means the Ghostty tab strip.

#+begin_example
default    "{hostname}: {workspace}"   ->   mymac: some-project
here       "{workspace} · {tab}"       ->   some-project · agents
#+end_example

In a narrow tab, =\{hostname\}= spends characters on a constant, while =\{tab\}=
says which layout you are looking at. Tokens: =\{hostname\}=, =\{workspace\}=,
=\{tab\}=, =\{pane\}=, =\{terminal_title\}=.

*Caveat:* the title renders on the *server*, so =\{hostname\}= names the host the
panes actually run on. Restore it if you start using =herdr --remote=.

** Custom commands

Arbitrary chords can launch a command in a popup, a temporary pane, or detached:

#+begin_src toml
[[keys.command]]
key = "prefix+alt+g"
type = "popup"          # or "pane" / "shell"
command = "lazygit"
width = "80%"
height = "80%"
#+end_src

* Verifying the setup

1. =herdr config check= -> =config: ok=
2. =ctrl+a= then =c= creates a Herdr tab. If nothing happens, Ghostty is still
   swallowing the prefix -- grep its config for =ctrl+a>=.
3. =ctrl+a= then =q= detaches; =herdr= reattaches with panes intact.
4. Drag-select copies; =cmd+v= pastes.
5. Shift+click a URL in a pane and note whether it opens -- this resolves the
   open question above.

* Notes and gotchas

- *Update channel.* =herdr update= self-updates the binary, drifting from the
  Homebrew-managed version. Prefer =brew upgrade herdr= so the package manager
  stays the source of truth.
- *Completions go stale.* They are generated from the binary; regenerate after
  upgrades that add subcommands.
- *Nesting.* Launching Herdr inside a Herdr pane is blocked unless
  =experimental.allow_nested = true=.
- *Notification permission.* =delivery = "system"= makes macOS prompt once.

* Command reference

#+begin_src fish
herdr                              # launch or attach
herdr --session <name>             # named session
herdr --remote <ssh-target>        # attach over SSH
herdr --default-config             # print commented default config
herdr status                       # client and server status
herdr config check                 # validate config.toml
herdr config reset-keys            # back up config, drop custom keybindings
herdr server stop                  # stop the server via its API socket
herdr server reload-config         # reload config.toml in place
herdr channel set stable|preview   # update channel
herdr completion fish              # shell completions
#+end_src

Subcommand groups over the socket API, each with its own =--help=:
=workspace=, =worktree=, =tab=, =pane=, =agent=, =session=, =notification=,
=integration=, =api=.
